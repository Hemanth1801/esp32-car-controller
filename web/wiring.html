ESP32 DEVKIT V1 / L298N

L298N connections & driving.

Motor output is enabled after Arm, with a 100% default power limit. Boot and disconnects leave the car stopped/disarmed. Set the motor supply for your motors' voltage rating. The terminal marked +12V is the motor supply input; it does not mean every motor needs 12 V.

The D number is the GPIO number, not the physical header position. With power off, remove both ENA/ENB jumpers before connecting D32/D33. Add 10 kohm pull-downs from ENA and ENB to GND to keep the driver disabled during boot or an unplugged ESP.

Power and the separate 5V-EN jumper

  1. Power ESP USB directly from unboosted 5 V. Use computer USB during uploads and the bank during untethered use. Use one ESP power input at a time; no boosted voltage connects to ESP power/GPIO.
  2. For the common L298N module, remove the separate 5V-EN regulator jumper and feed unboosted regulated 5 V into the module's 5V logic terminal. This is different from the ENA and ENB jumpers. Do not combine an external 5 V feed with the enabled onboard regulator. Check the module schematic if its labels or regulator arrangement differ.
  3. Connect the motor-rated supply (XL6009 output if suitable) to L298N VS / +12V and its negative to GND. Join ESP ground, driver ground, bank negative and converter negative. Route motor current directly through power wiring.
  4. Fit supply capacitors near the driver: 100 uF bulk plus 100 nF ceramic, with voltage ratings above the supply. Use the module's flyback diodes. Neither motor output wire connects permanently to ground.

The L298N accepts ESP32 3.3 V logic while its logic supply is 5 V. Its motor voltage capability is higher than the previously assumed driver. Motor rating, module component ratings, cooling and current still determine the usable voltage. A 5 V / 2 A bank provides 10 W shared by the system; boosting reduces available output current and the L298N has a load-dependent voltage drop.

Reference: ST L298 datasheet.

Shared Wi-Fi and desktop controller

  1. The configured ESP joins Burugupally_5G using the supplied local credential file. It uses 2.4 GHz Wi-Fi and gets its address from the router. Connect the computer and phone to the same local network. Router guest/client isolation must be off.
  2. Run start.cmd, then open http://localhost:8765. The launcher finds the paired ESP and saves its address. The website stays on this computer; the ESP receives command API requests only.
  3. For later uploads, use build-firmware.ps1 -Port COM7 with the actual USB port, or Arduino IDE: DOIT ESP32 DEVKIT V1, ESP32 core 3.x and ArduinoJson 7.4.3. If auto-reset fails, hold BOOT, tap EN/RESET, then retry; release BOOT when writing begins.
  4. The configured local firmware has motor output enabled. A fresh/example setup still defaults to disabled output. At startup and after stop/disconnect, release inputs and centre steering before pressing Arm.

Phone tilt controller

Connect the ESP, computer and phone to the same local Wi-Fi network. Close any existing desktop server window and run start-mobile.cmd on the computer. It prints the phone certificate-setup and HTTPS controller addresses. Open the setup address on the phone, trust the generated local CA once, then open the HTTPS controller. Tap Enable tilt, allow motion, Set centre, then Arm.

Hold the right half to accelerate, left half to reverse; tilt left/right to steer. Release to stop output. The power limit now defaults to 100%. Both halves together, interrupted touch/sensors, rotating, hiding the page, or lost connection disarm. Set centre again after rotating. With the configured steering-hold firmware, steering stays powered off-centre while armed; return to centre to release it. This controls motor effort, not a measured angle. Holding at an end stop draws stall current: verify motor voltage/current ratings and temperature before sustained turns. Fresh/example firmware retains the optional 250 ms pulse mode.

If Windows Firewall blocks the phone, run enable-phone-access.ps1 from an Administrator PowerShell window. It allows ports 8767/8768 only on the computer's Wi-Fi address, only from the local subnet. The computer must stay running.

First motor test

Raise the wheels before the first movement. Confirm the ENA/ENB jumper setup and correct supply, release inputs, press Arm, then test briefly. With 100% selected, full accelerator or the phone's drive button requests full duty. Power off before swapping a motor's two output wires to correct direction. The speed slider can lower the power setting.

W/S drive forward/reverse, A/D steer, Space stops/disarms. The brake pedal cancels throttle. Stop disables ENA/ENB (coast); it is not a measured mechanical brake. The optional command timeout stops/disarms after 400 ms without valid commands when enabled. The driving page reports whether the flashed firmware has it enabled. With timeout off, the last output can persist if commands stop. Wi-Fi loss still stops/disarms. In the configured hold mode, steering follows the requested PWM until centred or stopped. The optional pulse mode stops at 250 ms and requires neutral before another pulse. The diagram shows requested movement, not measured speed or wheel angle.

Connection checks

Check ESP power, the 2.4 GHz Wi-Fi credentials, firmware/relay token pairing, and router client isolation. Restart the launcher to rediscover the ESP if DHCP changes its address. Its current address is printed over USB at 115200 baud and saved in relay.local.json after discovery. The website runs on this computer, so the ESP address will not serve the page. Desktop mode is loopback-only; phone mode adds a local HTTPS address. Reconnection always needs explicit re-arming.
